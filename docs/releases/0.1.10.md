Set a coding agent's manner once and keep it across every project.

### Install or upgrade to this release

```bash
npm install --global tonedial@0.1.10
```

Use `tonedial update` for npm or curl installations; it asks before updating.
After updating, run `tonedial doctor` in the same scope to inspect application state.

### Changes

- Deliver long tones to Codex in full. Codex hooks now return the guide and tone
  as JSON `additionalContext` with `additionalContextLimit: 0`, so Codex no longer
  replaces context over about 2,500 tokens with a preview.
- Report Codex hooks written by earlier versions as stale in `doctor`.
  `doctor --fix` or `init` rewrites them; a project that inherits a global hook
  needs `tonedial init --global --tools codex`.
- Warn when Claude Code would cut the hook context to a short preview.
  Tone-changing commands and `doctor` name the 10,000-character cap, the measured
  total and the long settings to shorten; the change is still saved.
- Name Claude Code's workspace trust step in `init` and `wire` receipts, and
  offer to open Claude Code in a connected project after `init`.
- Tell `tonedial test` users that the preview sends the tone once, so they judge
  it by the first few replies.

Command names, options, JSON fields, saved tone settings and approval gates
remain unchanged.

Codex keys hook trust to the definition, so review a rewritten hook again in `/hooks`.
Earlier ToneDial builds cannot read a config written by this release;
use `tonedial doctor --fix --rollback <operation-id>` to restore the previous files.
