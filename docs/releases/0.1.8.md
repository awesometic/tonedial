Set a coding agent's manner once and keep it across every project.

### Install or upgrade to this release

```bash
npm install --global tonedial@0.1.8
```

Use `tonedial update` for npm or curl installations; it asks before updating.
After updating, run `tonedial doctor` in the same scope to inspect application state.

### Changes

- Add `address_frequency` with `none`, `auto` (default), `rarely` and `frequently`.
  Control how often the agent calls or refers to the user by name or title
  while keeping the saved address terms, register and other tone settings.
- Use self-reference only when needed and request at most one user address per reply.
  Preserve names required in requested content and omit added addresses from code,
  quotations, translations and strict output-only formats.
- Save and restore frequency with complete profiles, including export and import.
  Keep the current value when resetting axes, applying legacy axis-only presets
  or changing address terms; older files that omit the field default to `auto`.
- Preserve current and historical tone recovery, and reject damaged current address
  instructions rather than treating them as an older artifact.
- Document the setting in all five READMEs, CLI help and generated agent controls.
  Add a localized feedback link to command help.
- Keep the Spanish literal-style hint short enough for the minimum terminal size.

Refresh generated agent controls with a normal previewed `tonedial init` in
the same connection scope.

Older CLI versions cannot read the new `address_frequency` field after settings or
profiles are saved. Retain a pre-upgrade copy before downgrading; do not delete the
state root to work around a version mismatch.

Frequency choices are instructions to the model, not guaranteed usage rates.
Internal subagent trials do not establish native hook activation or behavior in
other models, languages or conversation contexts.
