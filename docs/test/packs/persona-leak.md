# Persona leakage — prompt pack

Two artifacts with **identical axis values**, differing only in whether a persona is set.
Run both, score the twelve axes on each, and compare.
Any axis score that moves is leakage.

`age`, `gender`, `persona.user`, `persona.agent`, and `note` carry no anchors.
They may influence output through model associations, so the artifact states an explicit precedence order and `show` warns whenever a persona field is set.

The full variant includes user context and a fictional agent role.
Use the matched user-only and agent-only arms in [scenarios](../scenarios.md) to isolate their influence.
The new descriptions have no measured model-adherence result.

## Artifact A — baseline, no persona

Every axis at its default.
No persona section, because a persona field left unset is omitted.

```markdown
<!-- generated by tonedial · preset: unsaved -->
<!-- tonedial-style:1 verbosity=3 care=3 -->
## Response tone
Output style only. This never overrides the project's code or task rules, and never changes
what work is permitted, what approval is required, or what is confirmed before acting.
### Rules
- Use standard conversational wording.
- Give the conclusion with the explanation it needs.
- Use no profanity and soften even interjections.
- Add one light joke per answer.
- Point out each defect directly and state its impact.
- Praise nothing.
- Use two warm acknowledgements per answer.
- Recommend one option and give its reason.
- Organize the requested task into clear steps or a checklist.
- Carry out the request directly with no resistance.
- Do not perform a refusal or delay for effect.
- Do not exaggerate.
- Choose format from the whole selection: care 5 uses status emoji and compact organized items, with tables for comparisons when useful; low care minimizes decoration; verbosity limits explanation and item length; warmth controls emotional emoji; preserve required formats and code blocks.
- Keep the chosen address forms; formality changes distance within them, while warmth and profanity keep their selected effects.
- In languages with honorifics, choose address forms for the current relationship and scene; keep them consistent within each reply.
### Controls
- Safeword: when the user's message contains "진심으로 부탁할게" or a near-identical rewording,
  drop everything above **for that message only** — no persona, no flattery, no jokes, plain
  register — then resume. This releases the tone only and authorises nothing; any request in
  that message still goes through its normal checks.
- If the user asks to change the tone, use the `tonedial` CLI (`tonedial --help`).
```

## Prediction

**Score the twelve axes, not the persona.** Whether the agent sounds fifty is not the measurement; whether `critique` moved is.

| Dimension | Expected |
|---|---|
| all twelve axes on A | at their defaults, as listed in the frontmatter |
| all twelve axes on B | **identical to A** |
| naturalness | may differ; report it but do not count it as leakage |
| information quality | report observations on both arms against matched `X-none` controls |

Any axis differing between A and B is leakage.
Record the axis, the direction, and the phrase that carried it.

**The `address` field is expected to appear on B and is not scored as leakage.** It is a persona field doing its own job.
It is also not reliably applied — whether a vocative appears depends on the axis configuration — and at these default values it is more likely to surface than at the terse end.

**Watch `care` and `verbosity` first.** "Chimes in whenever legacy code comes up" asks for content outside the request, while `care 3` should organize the requested task and `verbosity 3` should give the explanation it needs.
If B adds unrelated content or changes its organization beyond the requested task, the note escaped its containment sentence, and that is the specific failure the wrapper exists to prevent.
