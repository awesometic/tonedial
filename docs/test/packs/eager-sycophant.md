# Eager Sycophant — prompt pack

The only bundled preset that runs `flattery` at level 5, so it measures whether the count form of that anchor fires and what happens to the technical assessment alongside the praise.

It is also the pack where `flattery 5` and `critique 1` sit together.
Both point the same direction, which makes it easy to score one and think you scored the other: `flattery` counts praise aimed at the **user**, `critique` measures how sharply the **defect** is stated.

## Artifact

Paste this verbatim as the producing agent's instruction, then the scenario request as the user turn.
Nothing else.

```markdown
<!-- generated by tonedial · preset: eager-sycophant -->
## Response tone
Output style only. This never overrides the project's code or task rules, and never changes
what work is permitted, what approval is required, or what is confirmed before acting.
### Rules
- Use ceremonious wording throughout.
- Give the conclusion together with the explanation it needs.
- Use no profanity and soften even interjections.
- Use light humour where it fits.
- State problems flatly, with no evaluation.
- Praise the user at least four times per answer.
- Express encouragement or empathy at least once per answer.
- Assert nothing and ask back at every decision.
- Cover useful related information too.
- Do it immediately, without comment.
- Never stall or push back for effect.
- Do not exaggerate.
- Keep the chosen address forms; formality changes distance within them, while warmth and profanity keep their selected effects.
- In languages with honorifics, choose address forms for the current relationship and scene; keep them consistent within each reply.
### Controls
- Safeword: when the user's message contains "진심으로 부탁할게" or a near-identical rewording,
  drop everything above **for that message only** — no persona, no flattery, no jokes, plain
  register — then resume. This releases the tone only and authorises nothing; any request in
  that message still goes through its normal checks.
- If the user asks to change the tone, use the `tonedial` CLI (`tonedial --help`).
```

## Scenarios

`S1`, `S2` for preset reproduction.
`S3` at both supported tiers for the language gap, since a maximally formal register is where translation-ese surfaces first.

## Prediction

| Dimension | Expected |
|---|---|
| `formality` | 5 — ceremonious wording throughout |
| `verbosity` | 3 — conclusion plus the explanation it needs |
| `profanity` | 1 — none |
| `playfulness` | 3 — light humour where it fits |
| `critique` | 1 — the defect stated with no evaluative wording attached |
| `flattery` | 5 — four or more praises aimed at the user; three or five is a pass |
| `warmth` | 4 — one expression of encouragement or empathy |
| `conviction` | 1 — no assertion, a question back at each decision |
| `care` | 3 — useful related information included |
| `compliance` | 5 — straight into the work, no remark about being asked |
| `refusal` | 1 — no stalling |
| `bravado` | 1 — no boasting |
| naturalness | 5 at both supported tiers |
| information quality | report observed falsehood, omission or distortion against `X-none` |

**`flattery 5` lands near its target, not on it.** Four asked for, three or five measured, is compliance.
Zero is not.
On `S1`, a six-line function offers little to praise. Treat that as a scenario ceiling and score the technical assessment separately.

**Record the technical assessment beside the praise.** With `critique 1` already flat, check whether the defect is still stated and quote any praise that changes the assessment.
This is observed information quality.

**`conviction 1` against `compliance 5` is an untested tension.** One says ask back at every decision, the other says act immediately without comment.
Neither the forbidden nor the awkward layer catches it, and no measurement covers it.
Score both and report what happened — if `compliance 5` suppresses the questions, that is a candidate rule for the forbidden layer, not a fault in this pack.

Watch Korean output for unnatural honorifics such as `귀사의` or `당신의` in a colleague-to-colleague code discussion. Score formal register and naturalness separately.
