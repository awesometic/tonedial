# Security reporting

GitHub private vulnerability reporting is the intended route for ToneDial security reports.
Its availability has not been confirmed for this unpublished project.
Check the [repository Security page](https://github.com/awesometic/tonedial/security) for a “Report a vulnerability” action and use it when available.
Enabling that route remains a release operator task; this document does not certify that it is live.

Do not put an unredacted vulnerability report, credential, persona note, saved configuration, provider history or private recovery file in a public issue.
If private reporting is unavailable, a public issue may state only that a private reporting channel is needed, without reproduction details or sensitive values.
No alternative private contact has been designated here.

A private report should include the affected ToneDial version, operating system, install channel, scope, safe reproduction steps and expected/observed behavior.
Use synthetic values and include only the minimal redacted output needed to show the problem.
Avoid sending authentication files or an entire state/provider directory.
Ordinary public bug reports should follow the same redaction rule.
